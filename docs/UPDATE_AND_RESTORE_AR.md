# استرجاع الروابط وحل مشكلة التحديث في 3Esnap v2.2.0

## لماذا لم يُثبَّت الإصدار الجديد فوق القديم؟

Android لا يسمح بتثبيت ملف APK فوق تطبيق موجود إلا إذا تطابق **Application ID والتوقيع الرقمي** وكان `versionCode` أعلى. لا يكفي تطابق اسم 3Esnap أو الأيقونة.

- `com.snapclean.app`: التطبيق الأصلي SnapClean — تطبيق مختلف.
- `com.threee.snap.debug`: APK تجريبية من GitHub Actions، موقعة بمفتاح Debug. المفتاح محفوظ في Cache وهو ليس حلًا دائمًا؛ إذا تغيّر التوقيع فلن يحدث التطبيق الموجود.
- `com.threee.snap`: APK Release، تُوقَّع بالمفتاح الثابت الذي تُعدّه بنفسك في GitHub Secrets. لا يمكن تثبيتها كـ«تحديث» لنسخة Debug؛ هما تطبيقان منفصلان.

**لا تحذف التطبيق لإصلاح فشل التحديث مباشرة.** صدّر نسخة JSON واحفظها في مكان مستقل، ثم تحقق من معرّف الحزمة والشهادة. عند استخدام نفس Application ID ونفس المفتاح و`versionCode` أعلى، تبقى قاعدة البيانات المحلية أثناء التحديث. لا يمكننا استرجاع مفتاح توقيع Debug قديم من APK فقط.

للمساعدة في التشخيص على Windows مع Android SDK Platform Tools:

```powershell
adb shell pm list packages | findstr threee
adb shell dumpsys package com.threee.snap.debug | findstr versionCode
```

يمكن مقارنة البصمة باستخدام `apksigner verify --print-certs path\to\file.apk` من Android SDK Build Tools لكل ملف APK. إذا اختلف التوقيع بين القديم والجديد وكان لهما نفس Application ID، يلزم إما إعادة البناء بمفتاح التوقيع القديم أو الاحتفاظ بالنسخة القديمة وتصدير البيانات ونقلها لتطبيق مستقل. لا تُرسل مفتاحك السري لأي شخص.

## استرجاع ملف JSON الذي صدرته سابقاً

1. احتفظ بملف `3Esnap-links-YYYY-MM-DD.json` القديم؛ **لا تعدّله ولا تحذفه**.
2. افتح 3Esnap v2.2.0 ثم **الإعدادات ← استرجاع الروابط من نسخة JSON**.
3. اختر ملف JSON عبر منتقي ملفات Android، وليس زر **إضافة ملفات قديمة**.
4. سيُظهر التطبيق عدد السجلات التي تمت إضافتها، والسجلات المتكررة، وأي روابط تم ربطها بملفات في المكتبة بالفعل.
5. اضغط **المكتبة**؛ السجلات المفقودة تظهر برابط مصدرها، ومعها زر **إعادة تنزيل**. لا يستعيد JSON الوسائط نفسها.
6. لو ما زالت الفيديوهات والصوتيات في `Downloads`، أضفها عبر **إضافة ملفات**. عند تطابق اسم الملف ونوعه مع سجل مستعاد، سيتم ربط الملف بالسجل نفسه مع الاحتفاظ بالرابط.
7. بعد التأكد من الاستيراد، صدر نسخة جديدة من البيانات من **تصدير الروابط والبيانات** واحتفظ بها خارج الهاتف.

يدعم الاستيراد **صيغة schemaVersion 1 القديمة** والصيغة 2 الجديدة. لا يحذف سجلاتك الحالية، ويمنع تكرار السجلات التي تطابق ملفًا أو رابطًا موجودًا. عند فتح ملف معطوب أو من تطبيق آخر، تظهر رسالة خطأ بدلاً من استبدال المكتبة.

> ملاحظة: بعض روابط الوسائط قد تكون قديمة أو خاصة أو انتهت صلاحيتها. حفظ الرابط لا يضمن استمرار إمكانية إعادة التنزيل من الموقع.

## قص إطار الفيديو Crop بالشكل الجديد

1. المكتبة ← افتح الفيديو ← **قص الفيديو / Crop**، أو من خيارات الملف.
2. في محرر الفيديو اضغط **تحديد مساحة القص**.
3. ستظهر **شاشة مستقلة** فيها لقطة من الفيديو ومستطيل بأربع زوايا قابلة للسحب.
4. اسحب **داخل المستطيل** لتحريكه، أو اسحب إحدى **الزوايا الأربع** لتعديل حجمه. اختر **حر / 1:1 / 9:16 / 16:9**.
5. يمكنك تحريك شريط الوقت لعرض لقطة أخرى قبل اختيار الإطار (معاينة بإطار ثابت، وليست مشغل فيديو كامل داخل شاشة Crop).
6. اضغط **تطبيق القص** للرجوع لمحرر الفيديو، ثم **قص وحفظ** أو **قص ومشاركة**. خيار **إلغاء القص** يلغي اقتصاص الإطار مع الحفاظ على تحديد المدة الزمنية.
7. نتيجة القص ملف جديد، ولا تتغير النسخة الأصلية. قد يستغرق تصدير الفيديو بعض الوقت بسبب إعادة الترميز.

## إعداد توقيع Release ثابت لمستقبل التحديثات

1. على جهازك خارج مجلد Git، باستخدام JDK 17:

```powershell
keytool -genkeypair -v -storetype JKS -keystore 3esnap-release.jks -alias 3esnap -keyalg RSA -keysize 3072 -validity 10000
```

2. احتفظ بنسختين آمنتين من ملف `.jks` وكلمات مروره خارج GitHub والمستودع.
3. في مستودع GitHub، افتح **Settings → Secrets and variables → Actions**، وأنشئ أسرار Repository:
   - `ANDROID_KEYSTORE_BASE64`: محتوى ملف `.jks` بصيغة Base64.
   - `ANDROID_KEYSTORE_PASSWORD`: كلمة سر المخزن.
   - `ANDROID_KEY_ALIAS`: اسم المفتاح `3esnap`.
   - `ANDROID_KEY_PASSWORD`: كلمة سر المفتاح.
4. في PowerShell يمكن تحويل الملف إلى Base64 في متغير محلي (لا تشاركه علنًا):

```powershell
$encoded = [Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\\secure\\3esnap-release.jks"))
$encoded | Set-Clipboard
```

5. بعد تشغيل Actions بنجاح، نزّل Artifact باسم **3Esnap-signed-APK-...** وثبّت إصدار Release. **استخدم إصدارات Release الموقعة بنفس المفتاح فقط** لتحديث نفس تطبيق Release في المستقبل.

**مهم:** تحويل جهاز مثبت عليه Debug إلى Release لا يمكنه نقل البيانات آليًا بين معرّفيهما المختلفين؛ استخدم تصدير JSON ثم استيراده في Release.
