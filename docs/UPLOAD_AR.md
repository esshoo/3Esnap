# رفع تعديلات 3Esnap والحصول على APK

**لتحديث 2.1.0 فوق آخر نجاح في GitHub (2.0.2)**: فك ضغط حزمة Patch في جذر المستودع الحالي، راجع `git diff`، ثم ارفع الملفات المتغيرة. لست بحاجة إلى حذف المشروع أو إعادة استنساخه ما دامت نسختك متزامنة مع `main`.

## قبل البدء

هذه **حزمة ملفات معدلة ومضافة**، وليست APK ولا نسخة مستقلة كاملة من المستودع. يتم نسخها فوق نسخة Git مستنسخة من:

`https://github.com/esshoo/3Esnap`

لم يتم رفع أي تعديل إلى حسابك. احتفظ بنسخة من أي تعديلات محلية لديك قبل استبدال الملفات، ولا تحذف APK القديم أو تطبيقه من الهاتف.

## الطريقة الأولى: GitHub Desktop

1. افتح **File → Clone repository → URL**، ثم أدخل رابط المستودع وحدد مجلد الحفظ. إذا كان المستودع مستنسخًا بالفعل، افتحه بدل إنشاء نسخة ثانية.
2. اختر **Repository → Show in Explorer**.
3. فك ضغط الحزمة في مجلد مستقل. افتح المجلد الذي يحتوي على `app` و`.github` و`build.gradle`.
4. انسخ **كل المحتويات** إلى جذر المستودع المفتوح في Explorer. وافق على استبدال الملفات. لا تضع المجلد كله داخل مجلد جديد اسمه `3Esnap-update` داخل المستودع.
5. تأكد أن المسار النهائي للـworkflow هو:
   `.github/workflows/android.yml`
   وليس `3Esnap-update/.github/workflows/android.yml`.
6. اترك ملفات `LICENSE` و`gradlew` و`gradlew.bat` و`gradle/wrapper/gradle-wrapper.jar` الأصلية، وكذلك مجلد `.git`.
7. ارجع إلى Desktop. راجع قائمة **Changes**. لا يجب أن تحتوي على ملفات `.jks` أو `.keystore` أو `local.properties` أو مجلدات `build`.
8. اكتب عنوان commit مثل:
   `Brand as 3Esnap and add media library and APK workflow`
9. اضغط **Commit to main** ثم **Push origin**. إذا كنت تعمل على branch آخر، ارفع الفرع ثم ادمجه في `main`؛ التشغيل التلقائي للإصدار هنا مربوط بـ `main`.

## الطريقة الثانية: Terminal / PowerShell

إن لم تكن قد استنسخت المستودع بعد، نفّذ:

```powershell
git clone https://github.com/esshoo/3Esnap.git
cd 3Esnap
```

إن كانت نسخة المستودع موجودة بالفعل، افتح Terminal داخلها. راجع `git status` واحتفظ بتعديلاتك الحالية قبل نسخ الحزمة؛ لا تستخدم `reset --hard` أو حذف الملفات.

بعد نسخ محتويات الحزمة فوق جذر المستودع:

```powershell
git status
git diff --stat
git add .
git commit -m "Brand as 3Esnap and add media library and APK workflow"
git push origin main
```

الأمر الأخير يفترض أن الفرع الحالي `main`. تحقق باستخدام `git branch --show-current`. لا تستبدل تاريخ Git ولا تستخدم force push. إذا طلب Git تسجيل الدخول، استخدم حسابك وصلاحياتك المعتادة ولا تكتب رمز وصول داخل الملفات أو الأوامر التي سترفعها.

## تشغيل GitHub Actions

1. افتح المستودع على GitHub → **Actions**.
2. إن ظهرت رسالة أن workflows غير مفعلة بسبب كون المشروع fork، فعّلها من الزر المعروض. يمكن أيضًا مراجعة **Settings → Actions → General** والسماح بالإجراءات المطلوبة وفق إعدادات حسابك.
3. افتح **Build 3Esnap APK**. يبدأ تلقائيًا عند push إلى `main`، أو اضغط **Run workflow** واختر `main`.
4. عند انتهاء تشغيل ناجح افتح صفحة التشغيل، ثم قسم **Artifacts** في الأسفل.
5. نزّل **`3Esnap-debug-APK-رقم_التشغيل`** وفك ضغطه.

الملفات المتوقعة داخل حزمة Debug:

- `3Esnap-2.0.0-arm64-v8a-debug.apk`
- `3Esnap-2.0.0-armeabi-v7a-debug.apk`
- `3Esnap-2.0.0-x86_64-debug.apk`
- `3Esnap-2.0.0-universal-debug.apk`
- `SHA256SUMS.txt`

اختر APK واحدًا. `universal` هو الخيار المبسط عندما لا تعرف معمارية جهازك، لكنه أكبر حجمًا. النسخة `arm64-v8a` مخصصة للأجهزة التي تدعم هذه المعمارية، والنسخة `x86_64` مفيدة لمحاكيات متوافقة. انقل الملف إلى الهاتف وثبّته عبر مسار التثبيت الذي يسمح به جهازك. لا ترفع ملف APK أو أي مفتاح توقيع يدويًا إلى شجرة المصدر.

**لن يظهر APK عند فشل أي خطوة تحقق أو بناء.** افتح أول خطوة حمراء واقرأ سجل الخطأ. توجد Artifacts باسم `3Esnap-test-reports-…` عند توفر تقارير الاختبارات. لا تعتبر لقطة الواجهة أو نجاح اختبارات JavaScript دليلًا على نجاح تجميع Android.

## الفرق بين Debug وRelease

النسخة الافتراضية Debug موقعة بمفتاح تطوير، وليست ملفًا unsigned. معرّفها `com.threee.snap.debug`، ولذلك تُثبت بجوار SnapClean القديم.

يحاول workflow الاحتفاظ بمفتاح Debug في GitHub Actions cache لتحسين توافق التحديثات التجريبية. **الـcache ليس مخزنًا مضمونًا لمفتاح دائم**؛ قد يُحذف أو يُستبدل. لا تعتمد على Debug كتوقيع إنتاج. اختلاف المفتاح قد يمنع التحديث فوق النسخة السابقة. تصدير الروابط والاحتفاظ بالملفات مطلوبان قبل أي إزالة للتطبيق.

لنسخة ثابتة قابلة للتحديث على المدى الطويل، أنشئ مفتاح Release خاصًا بك واحتفظ به وبكلمات مروره خارج المستودع، ثم أضف الأسرار التالية.

## إعداد توقيع Release — اختياري

### 1. إنشاء المفتاح على جهازك

نفّذ الأمر داخل مجلد آمن **خارج المستودع**، مع وجود JDK و`keytool`:

```powershell
keytool -genkeypair -v -storetype JKS -keystore 3esnap-release.jks -alias 3esnap -keyalg RSA -keysize 3072 -validity 10000
```

سيطلب كلمات المرور وبيانات الشهادة. لا تشارك ملف المفتاح أو كلمة مروره علنًا. احتفظ بنسخة احتياطية آمنة؛ نفس المفتاح مطلوب لتحديث نفس التطبيق لاحقًا.

### 2. تحويل المفتاح إلى Base64

PowerShell، من مجلد المفتاح:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes((Resolve-Path ".\3esnap-release.jks"))) | Set-Clipboard
```

النص في الحافظة حساس مثل المفتاح نفسه. ضعه في GitHub Secret فقط، وليس في issue أو README أو المحادثة.

### 3. إضافة GitHub Secrets

داخل المستودع: **Settings → Secrets and variables → Actions → New repository secret**.

| اسم Secret | القيمة |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | النص المشفر بـBase64 من ملف المفتاح |
| `ANDROID_KEYSTORE_PASSWORD` | كلمة مرور ملف المفتاح |
| `ANDROID_KEY_ALIAS` | `3esnap` إذا استخدمت الأمر السابق |
| `ANDROID_KEY_PASSWORD` | كلمة مرور الـalias التي اخترتها، أو نفس كلمة مرور المفتاح عند استخدام ذلك الاختيار |

لا تحتاج إلى تعديل workflow لكتابة هذه القيم. عند وجودها كاملة، ينشئ workflow أيضًا `3Esnap-signed-APK-…`. لا تتاح أسرار الإصدار لخطوات pull requests في هذا workflow.

### 4. نشر إصدار في GitHub Releases

بعد نجاح البناء الموقّع على `main`، يمكن نشر tag جديد غير مستخدم:

```powershell
git tag v2.0.0
git push origin v2.0.0
```

عند اكتمال التشغيل بنجاح ووجود توقيع Release، تُرفع ملفات APK الموقعة وبصماتها إلى Release بهذا الوسم. لا يستخدم workflow مفتاح Debug لنشر Release، ولا ينشر APK unsigned.

الإصدار التالي يحتاج إلى تحديث `versionName` في `app/build.gradle` ووسم جديد. حاليًا `versionCode = 20000 + GITHUB_RUN_NUMBER`؛ احتفظ به متزايدًا، خصوصًا عند تغيير اسم workflow أو الانتقال لمستودع مختلف.

## ملفاتك القديمة وروابطها

افتح 3Esnap → **المكتبة → إضافة ملفات**، ثم اختر فيديوهاتك وصوتياتك القديمة. هذه العملية لا تنقلها ولا تحذفها.

الروابط الأصلية للملفات القديمة لا يمكن استنتاجها من الملف وحده؛ أضف الرابط من قائمة الملف → **إضافة رابط المصدر**. التنزيلات الجديدة التي ينشئها 3Esnap تحفظ رابطها تلقائيًا في السجل المحلي.

قبل حذف أي نسخة من التطبيق، صدّر الروابط من الإعدادات واحتفظ بملفات الوسائط. ملف JSON تصدير بيانات فقط، ولا توجد استعادة JSON تلقائية في هذا الإصدار.
