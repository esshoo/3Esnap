## اختبارات واشتراطات قبول v2.3.0

بعد الاختبارات المحلية ارفع الحزمة إلى `main` حتى يعمل `testDebugUnitTest`, `lintDebug`, `assembleDebug`. **فشل Lint أو APK يستلزم إصلاحًا ولا يجوز تجاهله.**

1. راجع التوقيع قبل تحديث التطبيق: الـApplication ID ثابت (`com.threee.snap.debug` في Debug)، لكن قد يفشل التثبيت إذا تبدّل مفتاح Debug من GitHub Cache. لا تحذف النسخة المثبتة إن كنت خزنت ملفات خاصة.
2. على Android7–9 جرّب إذن التخزين عند التنزيل التلقائي، وعلى Android13+ جرّب قبول/رفض إشعارات التنزيل. اختبر فحص رابط عام، واترك التطبيق بعد الفحص، وتأكد من وجود مهمة WorkManager وتصرفها وفق النظام.
3. اقطع الإنترنت أثناء التنزيل ثم أعد الاتصال. راقب انتقال الحالة إلى «بانتظار الشبكة»، وعودة المحاولة، ومنع المهمة المكررة، وإلغاء المهمة أثناء الانتظار. راجع سلوك force stop وإعادة فتح التطبيق.
4. اخفِ ملف فيديو/صوت أنشأه التطبيق بالبصمة، وتحقق من اختفاء اسمه وصورته من المكتبة وتصدير JSON. أغلق التطبيق وافتح الخزنة مجددًا؛ يجب أن يطلب مصادقة قوية. أعد الملف للمكتبة وتحقق من الاسم والحجم وإمكانية التشغيل. لا تختبر حذف التطبيق بملفات حقيقية قيمة.
5. استورد ملفًا من موفر SAF يمنع الحذف، جرّب إخفاءه: يجب أن تظهر رسالة فشل ولا يُعتبر مخفيًا. تأكد من عدم اختفاء الملف الأصلي بالخطأ.
6. قص مقطع فيديو 1.5–15 ثانية مع Crop، اختر «حفظ GIF» ثم «مشاركة GIF» وافحص نوعه `image/gif` والأبعاد والرسوم المتحركة، والسجل المرتبط برابط المصدر. تأكد أن MP4 الأصلي باقٍ.
7. جرّب مرشح الموسيقى على تسجيل حديث واضح، وقارن السماع قبل/بعد. **الاختبار لا يعني ضمان إزالة موسيقى كاملة.**
8. نزّل ثلاثة فيديوهات بعناوين تعليمية/ألعاب/أخبار، وتحقق من التصنيف المقترح، عدّله يدويًا، وابحث حسب التصنيف والعنوان والرابط. تأكد من عدم تسرب ملف مخفي في البحث.
9. تأكد من استرجاع JSON القديم وأنه لا يمحو التصنيفات أو البيانات المكتملة، وأن ملفات الخزنة لا تدخل JSON.


## اختبارات إضافات v2.2.0

- فحوصات Java بدون Android SDK لصيغ JSON وروابط المصدر (`BackupRulesSelfTest`).
- فحص بنيوي للتصدير والاستيراد واندماج SQLite وحدود حجم JSON، ووجود شاشة Crop ونقل الاختيار إلى FFmpeg.
- اختبارات Chromium في وضع DOM محلي مع جسر Android وهمي: زر استرجاع JSON مستقل وإعادة تنزيل السجلات المفقودة، واستمرار اختبار الشبكة/القائمة وعدم التمرير الأفقي.
- اختبارات EditPlan لقص المدة والإحداثيات وأوامر FFmpeg.

**لا توجد تجربة تحميل JSON فعلية داخل جهاز أندرويد أو تنفيذ SQLite على Android في بيئة الاختبار المحلية. الاختبار الحاسم هو نجاح GitHub Actions ثم الاستيراد على الهاتف.**

## اختبار المحرر على الهاتف

1. افتح ملفًا مكتملًا من المكتبة ثم اضغط «قص الفيديو» أو «قص الصوت»، أو افتح قائمة الملف واضغط «قص».
2. حرّك بداية ونهاية المقطع، جرّب المعاينة والتعيين من موضع التشغيل، ثم نفّذ «قص وحفظ» وتأكد أن الأصل لم يتغير.
3. للفيديو، فعّل «قص الإطار» واختبر القص الحر والمربع والعمودي والأفقي، مع سحب موضع المستطيل ومقبض تعديل الحجم.
4. نفّذ «قص ومشاركة» وأرسل المقطع الناتج إلى تطبيق آخر، وتأكد من أن المقطع **ليس الملف الكامل**.
5. تحقق من ظهور الملف الناتج في Downloads/3Esnap وظهوره في المكتبة مع رابط المصدر القديم.
6. اختبر قلة التخزين وملفًا مستوردًا من مزود SAF وإلغاء المعالجة، واختبر تحوّل التطبيق للخلفية أو تدوير الجهاز أثناء التحرير.

# تقرير الاختبارات وحدود التحقق

## ما تم تشغيله محليًا في الإصدار الأساسي 2.0.0 (مرجع تاريخي)

| الفحص | النتيجة | ما الذي لا يثبته |
|---|---|---|
| `python tools/check_project.py` |96 فحصًا ناجحًا | ليس Android Lint أو تجميع APK |
| `bash tools/check-java.sh` |40 assertion ناجحًا بعد تجميع سياسة الروابط/الأسماء بـJava17 | لا يجمع الكلاسات المعتمدة على Android SDK |
| Java parser ضمن السكربت السابق |11 ملف Android Java تم تحليل بنائها النحوي | ليس type-check ضد Android/AndroidX/yt-dlp |
| `node --test tests/web.test.cjs` |23 اختبارًا ناجحًا | لا يختبر WebView على هاتف |
| `tests/ui_smoke.py` |26 تحقق تفاعل ناجحًا داخل Chromium في وضع offline-dom | الجسر الأصلي وبيانات الملفات محاكاة؛ لا يوجد تنزيل حقيقي أو تشغيل وسائط أصلي |

وضع الاختبار المحلي `offline-dom` يستخدم HTML/CSS/JS الفعلية مع bridge تجريبي وذاكرة تفضيلات محاكاة. استُخدم لأن سياسة متصفح بيئة التسليم تمنع التنقل حتى إلى localhost. **هذا الوضع لا يختبر CSP أو أصل الصفحة أو استمرارية localStorage الحقيقية عبر عملية متصفح جديدة.** وضع CI الافتراضي يستخدم خادم HTTP محليًا وlocalStorage فعلية؛ لم يُشغّل ذلك الوضع هنا.

نجحت تفاعلات الشبكة والقائمة، التصفية والبحث العربي وبالرابط، الفرز، تمرير ID الصحيح للتشغيل/المشاركة/فتح المصدر، إضافة رابط لملف مستورد، قائمة الإجراءات واحتجاز التركيز، إعدادات الوضع والتفضيلات، تمرير اختيارات التنزيل، إبطال بيانات الرابط عند تعديله، تجاهل الردود القديمة، عدم تفسير عنوان الملف على أنه HTML، الملفات المفقودة، الحالة الفارغة، pagination لـ137 سجلًا، وعدم وجود تمرير أفقي على عروض320/360/412/768/1024px.

لقطات المعاينة — إن كانت مرفقة مع التسليم — تعرض **بيانات تجريبية وليست تنزيلات تمت بالفعل**.

## ما لم يُنفَّذ محليًا

لا يوجد Android SDK أو إمكانية تنزيل تبعياته في بيئة التسليم. لذلك **لم يتم تشغيل Gradle، ولم تنجح أو تفشل هنا مهمة assembleDebug، ولم تتولد APK**. لم تنفذ Android Lint ولا اختبارات JUnit التابعة لـGradle ولا اختبارات جهاز/محاكي.

لا يوجد تأكيد عملي حتى الآن على تنزيل روابط المنصات أو صلاحيات MediaStore/SAF أو تشغيل/مشاركة الوسائط أو إشعارات الخدمة على جهاز فعلي. هذا يجب اختباره قبل الاستخدام الإنتاجي، وليس افتراضه من نجاح اختبارات الواجهة.

## ما ينفذه workflow بعد الرفع

- فحوص البنية والسياسة وJavaScript.
- اختبارات Chromium على أصل HTTP محلي مع bridge تجريبي، دون وضع offline-dom.
- التحقق من Gradle wrapper، إعداد JDK17 وSDK35، ثم `testDebugUnitTest` و`lintDebug` و`assembleDebug`.
- إنشاء Release موقعة فقط عند وجود أسرار التوقيع كاملة.
- التحقق من توقيع ملفات APK قبل نشر Artifacts، وكتابة SHA-256.
- رفع تقارير الاختبارات وLint عند توفرها، حتى عند فشل التشغيل.

## تشغيل الفحوص المستقلة

```bash
python3 tools/check_project.py
bash tools/check-java.sh
node --test tests/web.test.cjs
python3 -m pip install playwright==1.55.0
python3 -m playwright install chromium
python3 tests/ui_smoke.py
```

لبيئة محلية تمنع التنقل لكن تسمح بإنشاء DOM اختبار، الخيار التشخيصي فقط:

```bash
UI_TEST_MODE=offline-dom CHROMIUM_BINARY=/usr/bin/chromium python3 tests/ui_smoke.py
```

لا تستخدم هذا الخيار لتدّعي اختبار أمان أصل WebView أو التخزين الحقيقي.

## اختبار قبول على الهاتف بعد نجاح البناء

1. ثبّت Debug بجوار SnapClean وتحقق من الاسم والأيقونة على مشغل الهاتف. اختبر Android7/9 وAndroid10+ وAndroid13+ وAndroid15+ كلما أمكن، وأجهزة16KB pages قبل إعلان دعمها.
2. استخدم روابط عامة تملك حقوق تنزيلها. افحص البيانات، نزّل MP4 بجودة محددة وMP3، ثم تحقق من الصيغة الفعلية والتشغيل وليس امتداد الملف فقط. كرر لروابط المنصات التي تحتاجها.
3. ابدأ أكثر من تنزيل، ألغِ ملفًا في الانتظار وآخر أثناء المعالجة، ثم أعد المحاولة بعد انتهاء الإلغاء. تحقق من عدم ظهور ملف مبتور أو تكرار محفوظ.
4. انتقل لتطبيق آخر أثناء التنزيل، ثم عد. اختبر رفض إذن الإشعارات، وإلغاءه من الإشعار عند السماح به. اختبر قطع الإنترنت وقلة المساحة وإغلاق التطبيق بالقوة ثم إعادة فتحه.
5. افتح المكتبة، بدّل شبكة/قائمة، ابحث وفرز وفلتر، ثم أغلق التطبيق وافتحه للتحقق من البيانات والتفضيلات.
6. شغّل صوتًا وفيديو، حرّك شريط التقدم، أوقف مؤقتًا، أدر الجهاز، افتح مشغلًا آخر. اختبر ترميزًا غير مدعوم واستجابة رسالة الخطأ.
7. شارك ملفًا إلى تطبيقين مختلفين، وانسخ رابط المصدر وافتحه وشاركه. يجب فتح المصدر خارج WebView المحلي.
8. استورد ملفًا قديمًا من منتقي Android، أضف مصدره، ثم تأكد أن إزالة السجل لا تحذف الملف. انقل ملفًا خارج التطبيق ثم اضغط تحديث المكتبة للتحقق من حالة الملف المفقود.
9. جرّب حذف ملف أنشأه التطبيق مقابل إزالة السجل فقط، وتحقق من النتائج في مدير الملفات.
10. صدّر JSON وتحقق من العناوين والروابط وعدم احتوائه على بايتات الفيديو. اختبر تحديث المحرك بعد انتهاء الطابور.

## مراجعة أمنية إضافية مقترحة

اختبارات URL redirects/DNS، ملفات وسائط غير موثوقة، حجوم مكتبة كبيرة، دورة حياة الخدمات عند تبدل الشبكة/النظام، قواعد Android16KB، وتحديثات تبعيات الطرف الثالث. لا توصف هذه الحزمة بأنها خضعت لتدقيق أمني كامل.
